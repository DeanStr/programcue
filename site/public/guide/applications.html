Applications

Applications is the organiser workspace for the call for speakers: the form, the public apply link and the queue of drafts and submissions.

Build and publish the form

  1. Open Applications, then open the form builder.
  2. Add questions, mark the required ones, and hide later questions until they apply.
  3. For a blind review, mark which answers evaluators may see. Unmarked answers are treated as identifying and stay hidden.
  4. Use preview, including test submission, to walk a branch without creating a real application.
  5. Publish the form. That locks this version. Later edits become a new version. People who already started a draft keep the version they started.

The public address is app.programcue.com/apply/ plus the form slug. Only a published form accepts new applications.

How people apply

Applicants open the published link. They can start without signing in, or sign in so they can return from Applications in the participant workspace. They can also pull in one public Sessionize speaker profile. That is not a Sessionize login.

Speakers and submitters have a shorter walkthrough in Speak or submit.

Drafts and recovery

The form saves as the applicant types and shows Saving, Saved, Offline or Retry required. Refreshing brings back the last saved draft. If two tabs both have unsaved edits, the applicant must resolve the clash.

A draft started without signing in stays in that browser. A signed- in draft belongs to that person. If confirmation email is not set up, that failure is shown. It is not hidden behind a successful submit.

Co-speakers

An applicant can name co-speakers. Each person gets a claim link that expires. They join the application, and can get workspace access, when they claim. Until then they are only a name on the form.

The applications list

Open Applications to filter, page and open a record. Saved views remember a filter you reuse. A record shows the answers, files and current review state.

If a proposal arrived outside the form, create an application record yourself. That does not invent a public submission.

Direct sessions and imports

Create a direct session when the session should exist without a public application, then attach speakers. For a bulk move, use CSV import or export from Operations. Preview the change, then confirm.
