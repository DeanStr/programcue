Product film

Product film transcript

A text equivalent of the six-minute, music-led film, including its visual narrative and on-screen product evidence.

0:00 — The program journey

[Instrumental music.] A keynote speaker faces a waiting audience. Program Cue appears beside the current program’s readiness picture. “Run the program. Not the spreadsheet.” closes the opening.

0:15 — One connected workspace

Scene 2 — One workspace maps the program lifecycle. Shape, Decide and Share organise the connected steps. The Command Centre replaces the lifecycle diagram.

0:31 — Event readiness

Scene 3 — The Command Centre shows event readiness. The current snapshot reads 80 percent with one critical condition. “Do this next” ranks the critical work. The action links to the filtered critical-work list.

0:54 — Event settings

Scene 4 — Event settings define shared identity and access. Program Cue is the default data store; Airtable is explicit. Branding previews appear at desktop and mobile sizes. A confirmed publish step makes the identity public.

1:17 — Applications

Scene 5 — Five steps govern a versioned application. Conditional questions, opening dates and submission caps stay together. Desktop and mobile previews remain clearly labelled. Publishing opens stable form version 01 for applications. An applicant recovers a private draft. Final submission retains the exact published version.

1:50 — Reviews and decisions

Scene 6 — An evaluator opens the review queue. The workbench combines answers, version and conflict status. Four weighted scores produce a total of 4.25. Optional advisory AI remains off until an administrator opts in. A reviewer returns an unavailable assignment without submitting a review. The main reviewer submits an owned recommendation. Two reviews support a released waitlist decision.

2:26 — Speaker preparation

Scene 7 — An accepted session opens speaker preparation. Speaker, Moderator and Chair responses remain independent. Tasks, role responses and files stay in view. The speaker deck completes secure file checks. Event imagery connects speaker preparation to show day.

2:59 — Event Assistant

Scene 8 — The Command Centre opens the Event Assistant. The organiser asks for a draft reminder for approval. Authorised records identify a separate outstanding handbook task. A draft reminder preview names one recipient. The organiser reviews the exact recipient and action. Approval queues the reminder. Provider acceptance remains pending. The AI result receives focused feedback. “Helpful” is saved. The rating can be changed.

3:34 — Communications

Scene 9 — A speaker welcome opens for review. Alex Morgan’s personalised preview appears. Confirmation rechecks the recipient and template. Queue acceptance and provider result remain separate. Calendar events keep stable identity through change.

4:00 — Schedule publication

Scene 10 — Conflict-aware scheduling moves towards publication. Two Main Hall sessions overlap at 10:30. Scenario Lab saves a named selection. Later application changes only the active draft. The exact public-content revision moves from In review to Approved. The full publication diff shows one moved session and one public-content change before confirmation. Publication rechecks conflicts, content, participation and public dependencies. Latest digest keeps exact counts and highlights.

4:40 — Public programme

Scene 11 — Seven connected examples share published program data. Program and timetable views appear on two screen sizes. A mobile program filters to one selected date. Speaker profiles link people to published sessions. A personal itinerary holds four saved sessions. A managed embed shows the published program. Light, dark and mobile site views appear. Event imagery brings the program to life.

5:16 — Integrations and recovery

Program Cue connects to your stack through 33 documented API paths. The contract explorer shows scoped keys and schemas. Operation recovery follows one reminder to a failed result. The failed operation keeps its original one-person audience. The Accelevents mapping preview awaits confirmation.

5:42 — One connected system

Scene 13 — The product journey resolves into one system. Shared source. Visible ownership. Clear next move. “From first proposal to published program” resolves into the ProgramCue.com closing card. Picture fades.
