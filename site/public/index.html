Three moves from open call to published programme.

Conference programmes rarely stall because a team cannot make a decision. They stall when the context is split across forms, spreadsheets, inboxes and calendars. Program Cue keeps each decision attached to the work it affects, so nothing has to be rebuilt by hand at the next step.

  1. Review

    Move from proposal to decision

    Open the call, review what arrives against real criteria, and turn an accepted proposal into a session without retyping it.

  2. Ready

    Act on readiness, not guesswork

    See exactly which speakers, tasks and messages are holding the programme up, weeks before they become programme-day problems.

  3. Publish

    Publish from a checked schedule

    Build across rooms and tracks, clear the blocking conflicts, then publish an exact snapshot for attendees and partners.

Everyone works from the same programme.

Organisers, reviewers, speakers and attendees each see the part that belongs to them, from one connected set of records rather than four separate copies of the truth.

  • Programme chairs and organisers

    Set up the event, run the call, watch readiness and publish the schedule when it is genuinely ready.

  • Review committees

    Score only what you are assigned, declare conflicts honestly and moderate towards a decision the chair can defend.

  • Speakers and submitters

    One portal from first proposal to stage, so nobody has to search an inbox for what the organisers asked for.

  • Attendees and the public

    A published programme people can actually use, generated from the schedule your team already maintains.

Designed for consequential programme work.

Program Cue makes access, publication and external work explicit. It does not hide missing credentials, provider failures or schedule blockers behind simulated success.

  • Permission-aware by default Private work is isolated by organisation, event and role.
  • Consequences stay visible Material changes use preview, confirmation and honest progress.
  • Publication is deliberate Public programme endpoints expose published snapshots only.
  • Private files stay private Uploads remain quarantined until their required checks clear.

Keep the tools around your programme in step.

Connect calendars, delivery and event-data services where they remove duplicate work. Each connection has an explicit purpose, and Program Cue reports provider failures instead of pretending an external action succeeded.

Purpose-built connections

  • Google and Microsoft calendars Keep Program Cue-managed session invitations current.
  • Resend Deliver programme email with visible delivery results.
  • Airtable Use an existing base as explicit programme authority.
  • Accelevents Preview, export and reconcile published event data.
Google permissions and data use

Google Sign-In can be used to create or access a Program Cue account. Users may also optionally connect Google Calendar so Program Cue can create, update, cancel and reconcile session invitations managed through Program Cue.

  • Sign-in: openid, email and profile, used only to authenticate you and to create or match your Program Cue account.
  • Optional calendar connection: https://www.googleapis.com/auth/calendar.events.owned, used only for Program Cue-managed invitations on your primary calendar.

The calendar connection is optional and can be disconnected at any time. Program Cue does not provide general calendar browsing and does not use Google Calendar data for advertising.

Before you start.

The questions programme teams ask most often when they are deciding whether Program Cue fits how their event runs.

Do attendees need an account to read the programme?

No. A published programme is public: a web page anyone can read, a calendar feed they can subscribe to, and read-only endpoints that expose published data only. Unpublished planning stays inside the event workspace.

Where can we learn how to use Program Cue?

The product guide walks through accounts, event setup, applications, review, speaker readiness, scheduling, communications and publication in the same language as the application.

How do speakers and reviewers get access?

An organiser invites them, or a published form gives applicants a way in. Access is granted per organisation, event and role, so a reviewer sees the review workbench and a speaker sees their own sessions, tasks and files.

Can we bring across the event we already run?

Yes. Import sessions, people and results as CSV, pull a public Sessionize speaker profile into an application, keep an existing Airtable base as the record of authority, or clone a previous Program Cue event and edit it.

What happens when the schedule changes after publication?

Program Cue records a new version snapshot, rechecks the blocking conflicts, and republishes only when you say so. Calendar invitations that Program Cue manages are updated or cancelled to match.

Is it usable without a mouse?

Scheduling offers keyboard alternatives to every pointer-driven action, and focus is preserved when dialogs close. These public pages are checked against WCAG 2.2 AA in the release gate.

Where does our data live?

On Cloudflare infrastructure, encrypted at rest, with uploaded files kept private and quarantined until their checks clear. The privacy policy sets out each provider and what it is used for.
